## 2. What the doctor sees

```
Dossier patient (drawer from the consultation · or the chart page under its own header)
 ├─ header (drawer only; the chart page keeps its header with « Planifier » / « Démarrer »)
 │    initials · full name · « 34 ans · Femme · +216 … » · « Patient externe » / « Patient OmniCare » (+ « Accès autorisé jusqu'au … »)
 ├─ Résumé      Informations essentielles · Médicaments (Actuels / Anciens) · [Mesures corporelles] · Dernière consultation · « Activité du dossier »
 ├─ Historique  Historique des consultations · N consultations · search · cards (lazy detail) · « Afficher plus »
 └─ Documents   N documents · list with « Aperçu » · or « Aucun document médical disponible »
```

**Visual language** (from the Flutter `patient_passport` widgets; no fixture data copied):
- cards with a 40 px tinted icon tile + title + subtitle (`PassportSectionHeading`);
- one row per essential item with a small tinted tile (blood type in error tint, allergies in amber, antécédents in violet);
- chips for list values;
- a segmented « Actuels / Anciens » control;
- « Actif / Terminé » tags;
- history cards with a status dot and a chevron.

All of it uses the `--oc-*` tokens and NG-ZORRO (`nz-segmented`, `nz-tag`, `nz-skeleton`, `nz-input`), plus `oc-tabs`, `oc-button`, `oc-empty-state` and `app-chart-access-required`. Shared styles: `record/record-cards.scss`.

### 2.1 Résumé
- **Informations essentielles** (« Informations prioritaires pour les professionnels de santé »):
  - Groupe sanguin: value, or « Non renseigné ».
  - Allergies et réactions: « Aucune allergie connue » / « Non renseigné » / chips (amber).
  - Antécédents / conditions chroniques: « Aucun connu » / « Non renseigné » / chips.
  - The three states come from the server's `allergiesStatus` / `conditionsStatus`. An older server without the status falls back to: a list means LIST, nothing means UNKNOWN.
- **Médicaments** (« N traitement(s) actif(s) »):
  - `GET /chart/medications?state=current` loads first; « Anciens » loads `state=past` the first time it is chosen.
  - Row: name (+ strength), « dose unité · N× par jour · pendant X jours/semaines/mois » or « au long cours », « Prescrit le JJ/MM/AAAA », and an « Actif » / « Terminé » tag computed from `endsAt` against today in Africa/Tunis.
  - Empty state: « Aucun traitement en cours ».
- **Mesures corporelles** (« Données renseignées par le patient »): taille, poids, IMC computed to one decimal. **Hidden** when there is no height and no weight.
- **Dernière consultation**: the most recent COMPLETED item (date, motif, diagnostic). « Voir dans l'historique » switches to Historique with that card open.
- **« Activité du dossier »**: a link at the bottom that shows the former administrative timeline inline (the existing `ChartHistoryTab`; its « Voir » links go to Historique / Documents).

### 2.2 Historique
- « Historique des consultations » · « Visites, diagnostics et ordonnances » · « N consultations » (server `total`).
- **Search** (motif or main diagnosis, case- and accent-insensitive) over the loaded items. **« Afficher plus »** loads the next keyset page (`cursor`, size 20).
- **The current consultation** (when opened from the consultation) is pinned first as « Consultation actuelle · en cours ». It is not expandable and is never duplicated below. Other in-progress / aborted consultations are plain rows with « En cours » / « Interrompue ».
- **Completed consultation:** a collapsed card (date + time in Tunis, « Dr … · spécialité », motif, status dot). Expanding fetches `GET /chart/consultations/{id}` **once**; the result is cached for the view, and only a failure is fetched again. It shows:
  - Diagnostic(s) with « Confirmé / Provisoire / Écarté »;
  - Traitement: « Aucun médicament », or each line (« 1 g · voie orale · 2× par jour · pendant 1 semaine », « au long cours », instructions);
  - Examens et orientation (« Analyse · NFS »);
  - Suivi (« Aucun suivi » / « Si besoin » / « Contrôle le JJ/MM/AAAA »);
  - Documents générés: one button per document, « Ordonnance », « Arrêt de travail du … au … », « Certificat médical ». A repeated label gets « (2) », so two identical buttons are impossible. Disabled until the PDF is ready;
  - « Voir les notes »: histoire, examen clinique, évaluation, notes, collapsed.
- **A completed consultation the server does not share** (`clinicalAvailable:false`) is listed but not expandable.
- **RESTRICTED:** one « Accès requis » block at the top, no search, rows with date, doctor and status only, nothing expandable, and no detail request (the store refuses it too).

### 2.3 Documents
The existing `ChartDocumentsTab` with `readOnly`: list, type icon, name, date, « Aperçu » (existing preview flow), « N documents », and « Aucun document médical disponible » when empty. No upload.

### 2.4 Where it is used
- **Consultation drawer** (P2c): `PatientRecordPanel` loads `GET /chart` and renders `PatientRecordView` with the current consultation id.
- **Chart page:** the page keeps its header (identity, tags, « Planifier un rendez-vous », « Démarrer la consultation »). The former 4 tabs are replaced by `PatientRecordView` with `showHeader=false`. The `?tab=` query parameter maps to the new tabs; an old `?tab=consultations` link lands on Historique.
- **Deleted:** `chart-consultations-tab.ts` and the former `getConsultations` API + DTOs. The static-demo fake API now implements the new calls (static-demo build passes).

### 2.5 Loading and access (frontend)
- `PatientRecordStore` is provided per view, so the drawer and the chart page each have their own.
- **Nothing is requested before it is shown:**
  - Résumé: summary + current medications + first history page (for « Dernière consultation »);
  - Anciens on demand;
  - each card's detail on expansion;
  - Documents when the tab opens.
- **No clinical call without clinical access:** `mayLoadClinical(access)` (mode OWNER or GRANTED and `clinical:true`) gates the summary, medications, details and documents. The history list is always allowed (the server returns the administrative view).
- A 403 « accès requis » answer renders the compact block, never the red error. A real failure renders a French message with « Réessayer ».

## 3. Backend read paths (§B)

Implemented by a delegated agent. I checked the controller mappings, the DTOs and the shared fixture in the code, and reconciled the frontend with the two deviations that change rendering (§3.2 items 2–3).

### 3.1 Contracts (all `/api/v1/patients/{id}/chart`, `Cache-Control: no-store`)

| Endpoint | Who | Response |
|---|---|---|
| `GET /consultations?cursor&size` (changed) | DOCTOR, SECRETARY | `{view, items, nextCursor, total}`. CLINICAL item: `{id, date, status, ownConsultation, doctor{name, specialty}\|null, clinicalAvailable, reason, diagnosisSummary}`. ADMINISTRATIVE item: `{id, date, status, ownConsultation, doctor}` only, with no MRS call. Keyset `(date desc, id desc)`; size default 20, **clamped to 50**; a bad `cursor`/`size` → 400 VALIDATION_ERROR (French). `total` = own (Spring count) + visible consultations of other professionals (MRS), never null |
| `GET /consultations/{cid}` (new) | DOCTOR; OWNER / GRANTED with the consultation-summaries section | Full detail (§2.2). Prescription v1/v2/v3 normalized (v3 codes when recognizable, otherwise the original text; v1 « 1 g » parsed). FINALIZED orders, FINALIZED artifacts with the sick-leave period and `downloadable` = render READY. RESTRICTED or no section → 403 `PATIENT_CHART_CLINICAL_ACCESS_REQUIRED` |
| `GET /medications?state=current\|past` (new) | DOCTOR; OWNER / GRANTED with the current-medications section | `{state, activeCount, items[{id, name, strength, dose, route, timesPerDay, frequencyText, duration, longTerm, startedAt, endsAt, prescribedAt}]}` from ACTIVE medication statements, structured fields read from the source prescription line. Current/past on today in Africa/Tunis. Missing state → 400 « Choisissez les traitements à afficher : en cours ou passés. » |
| `GET /medical-summary` (additive) | unchanged | `bodyMeasurements{heightCm, weightKg, measuredAt}\|null` (§3.2 item 1) |

- **Audit:** one Tier-1 event per clinical read (`CONSULTATIONS_READ`, `CONSULTATION_DETAIL_READ` linked to the consultation, `MEDICATIONS_READ`), plus MRS audit with the PATIENT_CHART purpose and the access mode.
- **No N+1:** one MRS call per request; doctor names come from one batch query per page or detail.
- **No clinical data in Spring tables or logs.**
- **MRS:**
  - new internal routes `doctor-chart/consultation-page`, `doctor-chart/consultations/{cid}`, `doctor-chart/medications`, plus `body_measurements` in `medical-summary`;
  - same chart access rule and visibility predicate;
  - **no SQL migration**.
- **Fixed on the way:** the medication projector now keeps the source item id needed to read a statement's structured line.

### 3.2 Deviations and decisions needed (from the backend work)
1. **B4 stopped for OMNICARE_GRANTED.** No ADR or grant section covers BODY_MEASUREMENTS, and the patient consent text for « Informations essentielles » lists only blood type, allergies and critical conditions. `bodyMeasurements` is therefore returned to EXTERNAL_OWNER only (null for a grant). External patients have no account, so nobody writes patient measurements for them today, and the card stays hidden everywhere for now. **Decision needed:** which grant section, if any, covers body measurements.
2. **Own completed consultation not visible in MRS** (e.g. a non-shareable one): B1 returns the 5-field summary with `clinicalAvailable:false` instead of 404, consistent with the list. The Angular card is then not expandable, and a detail opened anyway says « Le contenu de cette consultation n'est pas disponible. » **Confirm**, or switch to 404.
3. **In-progress / finalizing / aborted** → the 5-field summary, no MRS call and no audit (nothing clinical is read).
4. **Main diagnosis** (`diagnosisSummary`) = the first diagnosis that is not RULED_OUT. The former fallback to `assessment` is gone. **Confirm.**
5. **Medications** exclude statements superseded by a corrected prescription (also from « Anciens »). **Confirm.**
6. `total` counts ABORTED consultations too; the overview's `counts.consultations` still excludes them.

## 5. Points reported (frontend)
1. **Owner upload on the chart page is gone.** The prompt says « no upload in this view (the chart page keeps its own upload for the owner only if it already exists outside this component; don't add one) ». The only upload lived inside the former Documents tab, i.e. inside this component, so the chart page no longer offers « Ajouter un document ». The upload code (`ChartDocumentsTab` with `readOnly=false`) is kept, not deleted. **Decision:** put « Ajouter un document » back as a chart-page header action for the owner, or leave it out.
2. **Former Synthèse cards not in the new Résumé:** « Coordonnées » (date of birth, email, address, practice identifier) and « Prochain rendez-vous » are no longer shown on the chart page. The header line keeps age, sex and phone, and « Planifier un rendez-vous » stays in the header. Say if you want an administrative card back on the chart page (outside the medical view).
3. **« Activité du dossier »** opens inline below the link (not a dialog), which keeps it usable inside the drawer.
4. The history search covers the loaded pages only (as specified); « Afficher plus » extends it.
5. There is no Angular-side contract fixture for the new Spring JSON. The Angular models follow the contract given to the backend; the agent's final shapes match (checked field by field), with the two adaptations above.
