## 2. Error display timing

**Model.** Each section card (`motif`, `diagnostic`, `dossier`, `traitement`, `examens`, `suivi`, `documents`) carries `appConsultationSection`. Every error key belongs to one section (`sectionOfKey`: `clinicalRecord.diagnoses.*` → diagnostic, `prescription.*` → traitement, `order:*` → examens, `artifact:*` → documents…). `ConsultationUi` keeps a **revealed** set of error keys:

- **Leaving a section** (focusout to an element outside it) reveals that section's *current* errors.
- A **« Terminer » attempt** reveals every current error (live client rules + the four finish rules + server field errors), then scrolls to the first one.
- **Visible = revealed ∩ current.** Fixing a field removes it from the current errors, so its message disappears immediately, while focus is still in the field. The key is then dropped from the revealed set, so if the field breaks again (or a new error appears) it only shows at the next leave.
- **Server `fieldErrors`** from autosave join the current errors and follow the same rule. The save indicator still says « Non enregistré · champs à corriger » meanwhile; nothing is red until the section is left.
- The per-field `(blur)` touches and the per-medication-line focusout of P2b are removed.

**What is not a leave:**
- focus moving inside the card;
- focus moving into the CDK overlay container (select menu, date panel, a confirmation dialog);
- a focusout with no target right after a pointer-down inside an overlay (400 ms grace), e.g. a click on a date cell.

Opening or choosing in a select, a segmented control or a date picker therefore never turns anything red. Choosing a value also no longer marks the field as touched.

**Interpretation to confirm (§7.1):** the prompt says both "a field's error is never shown while focus is inside its section" and "fixing a field hides its error immediately". Read literally, they conflict. I applied: *no new error appears while focus is inside the section*; an error already revealed stays visible (and updates live) when the doctor comes back to fix it, so they can see what to fix.

  - `ChartMedicalSummaryCard` (already read-only);
  - `ChartDocumentsTab` with a new `readOnly` input: no « Ajouter un document » even when the server says `canUpload`;

- **Isolation:** the drawer only reads `ConsultationUi.recordOpen` and the patient's chart id. It does not touch the session store's drafts or queues. The page stays mounted behind the drawer, and the CDK scroll lock restores the scroll position on close.

## 7. Points reported

1. **"Never shown while focus is inside"** is applied to *new* errors only (§2). If you want the stricter reading (hide every error of the focused section), it is a one-line change in `visibleErrors`, but then a doctor fixing a field can't see the message while correcting it.
2. **Leaving to the header, the right column or outside the page counts as a leave**, as does opening the « Dossier patient » panel from the header. A confirmation dialog opened from a section does not (it is an overlay).
3. **Drawer width** is computed when the drawer renders (60% / 100% under 768 px). Rotating a phone while it is open keeps the width until the next render.
4. **The completed state still navigates** to the patient record: nothing can be lost there.
5. Unchanged from P2b and still open: the « Aucun connu » label for antécédents; « Annuler la consultation » / FINALIZING recovery (prompt 3); live run of the manual checklist.
