## 2. Design (what runs on the page)

```
ConsultationPage (route doctor/consultation/:id)
 ├─ providers: ConsultationSessionStore · ConsultationFinishFlow · ConsultationUi   (page-scoped, in memory only)
 ├─ ConsultationHeader        identity · « Rendez-vous de HH:mm · commencée à HH:mm » (Africa/Tunis) · save indicator · « Dossier patient »
 ├─ main column               1 Motif et examen · 2 Diagnostic · [3 Mise à jour du dossier médical] · Traitement · Examens et orientation · Suivi · Documents
 └─ right column              MedicalContextCard (read-only summary + recent history) · FinishCard (checklist + « Terminer »)
```

- **One draft per resource, one queue per draft.** Note, prescription, each order row and each certificate has its own `AutosaveQueue`. The queue holds the latest snapshot, debounces 1.5 s, sends at most one request at a time, and sends the latest snapshot once the request in flight returns (merging every change made meanwhile). The same value keeps the same `Idempotency-Key` across retries.
- **The page never overwrites what the doctor is typing with a server response.** A save only updates the version (and the server copy used for the fields the page does not edit).
- **Queue states** drive the indicator: `saving/pending` → « Enregistrement… »; `retrying` → « Non enregistré — nouvelle tentative… »; `offline` → « Hors ligne »; `conflict/failed/finalized` → « Non enregistré » (+ banner); `blocked/invalid` → « Non enregistré · champs à corriger »; otherwise « Enregistré · il y a N s ».
- **Retry:** status 0 / 408 / 429 / 5xx retry after `Retry-After` when present, else 2 s, 4 s, 8 s… capped at 30 s. Offline waits for the browser's `online` event.
- **Errors visible to the doctor** = live client errors (save rules) for touched fields + finish-only errors after a « Terminer » attempt + server field errors of the last rejected save (always). Leaving a medication card marks every field of that line as touched, so a line left without a duration shows its error.
- **Drafts are in memory only.** Nothing medical goes to `localStorage`, URLs or logs.

### 2.1 Field → contract mapping

| Section | Field | Payload | Client rule (Hard) |
|---|---|---|---|
| 1 | Motif * | `clinicalRecord.chiefComplaint` | ≤1000 characters; required to finish |
| 1 | Histoire de la maladie (counter /4000) | `history.presentIllness` | ≤4000 |
| 1 | Examen clinique | `clinicalFindings[type=EXAMINATION].description` | ≤2000 |
| 2 | Diagnostic / conclusion * | `diagnoses[0] = {system LOCAL, label, status}` | ≤500 (no `maxlength`, so 501 shows the error); required to finish |
| 2 | Provisoire / Confirmé | `diagnoses[0].status` | default Provisoire (§7.3) |
| 3 | Allergies / Antécédents | `medicalSummaryUpdate.{allergies,conditions} = {status, items}` | LIST needs ≥1 item, ≤50 items, ≤160 characters each. Only changed parts are sent (null = unchanged). EXTERNAL_OWNER only |
| 3 | Groupe sanguin | `medicalSummaryUpdate.bloodType` | `UNKNOWN` or one of the 8 groups |
| 4 | Aucun médicament / Prescrire * | `medicationDecision` | required to finish |
| 4 | Each line | `prescription.medications.N` (v3) | name ≤200; dose >0 (comma accepted); unit and route from the lists; 1–24 per day; duration required, DAY ≤365 / WEEK ≤52 / MONTH ≤12, stored as entered; quantity ≥1 if given; instructions ≤1000; ≤15 lines (config) |
| 5 | Type + cible | one clinical order per row | 2–500 characters after trim |
| 6 | Aucun suivi / Si besoin / Contrôle à une date * | `followUp` NO_FOLLOW_UP / FOLLOW_UP_AS_NEEDED / FOLLOW_UP_IN_PERIOD | date required for « Contrôle », ≥ today (picker disables past days); soft warning > 1 year |
| 7 | Arrêt de travail | SICK_LEAVE_CERTIFICATE `{statement, startDate, endDate}` | statement required ≤500; end ≥ start; ≤365 days inclusive (config); duration computed read-only |
| 7 | Certificat médical | MEDICAL_CERTIFICATE `{statement}` | statement required ≤500 |

Soft warnings (never blocking, no clinical threshold): the same drug twice (case/accent-insensitive), a follow-up more than a year away.

### 2.2 « Terminer »

1. `flushAll()`; if a queue is in conflict / retrying / offline / failed → message, stop.
2. Checklist (Motif, Diagnostic, Décision de traitement, Suivi) + any field error → fields in red, scroll + focus to the first invalid field, « Il manque : … » (each item is a link). Stop.
3. Confirmation « Terminer la consultation ? L'ordonnance et les documents seront signés et ne pourront plus être modifiés. »
4. Sign prescription (if Prescrire and still DRAFT) → finalize each DRAFT order → finalize each DRAFT certificate → `GET /{id}` (current version) → `GET finish-readiness` → `POST finish`. The button shows « Signature de l'ordonnance… », « Validation des examens… », « Signature des documents… », « Clôture… ».
5. `missing[]` → the same « Il manque » list, French labels (`CHIEF_COMPLAINT_MISSING` → « Motif de consultation »).
6. `409 FINISH_IN_PROGRESS`, `503 MRS_CONTEXT_PENDING`, `503 FINISH_RECONCILIATION_REQUIRED` → « Clôture en cours… », poll `GET /{id}` every Retry-After seconds for 2 minutes, then « La clôture prend plus de temps que prévu. Réessayez dans un instant. ». Only `status: COMPLETED` is success. A page opened in FINALIZING polls the same way.
7. Success → « Consultation terminée » + « Retour à l'accueil » + « Ouvrir le dossier patient ». Autosave stops.
8. Any failure midway leaves the consultation open with a French message; « Terminer » again skips what is already signed and reuses the Idempotency-Key of an ambiguous (0 / 5xx) attempt.

### 5.1 B1 — Duration units
- Prescription v3 accepts `duration {value, unit: DAY|WEEK|MONTH}`: DAY 1–365, WEEK 1–52, MONTH 1–12, **stored as entered** (MRS `records/prescription_v3.go`; Spring `PrescriptionContent.DurationUnit`, `PrescriptionContractValidator`).
- Already-written v3 (DAY) records stay readable byte-for-byte: canonical bytes from the pre-change validator are compared exactly.
- Errors: `prescription.medications.N.duration.value` `OUT_OF_RANGE` (min 1, max = the unit's cap; the Spring message is chosen from that max: « Durée entre 1 et 365 jours / 52 semaines / 12 mois. »); `….duration.unit` `INVALID_VALUE` / `REQUIRED`.
- **Pre-existing MRS defect fixed on the way:** `medications/projector.go` handled only v1/v2, so a signed v3 prescription failed projection (2a said it was handled). v3 now projects like v2: DAY + N days, WEEK + 7N days, MONTH + N calendar months, long-term → no end date.
- Shared fixture `security-contract/prescription-v3-spring-request.json` has a second line with `{2, WEEK}`; both layers' contract tests pass, plus a 13-month case failing on `medications.1.duration.value` max 12.

### 5.3 B3 — Discard drafts

| Endpoint | Success | Refused |
|---|---|---|
| `DELETE /doctor/consultations/{id}/clinical-orders/{orderId}?expectedClinicalOrderVersion=n` | 204 | FINALIZED → 409 `CLINICAL_ORDER_ALREADY_FINALIZED`; stale → 409 `CLINICAL_ORDER_VERSION_CONFLICT`; missing / another doctor's → 404 `CLINICAL_ORDER_NOT_FOUND` |
| `DELETE /doctor/consultations/{id}/artifacts/{artifactId}?expectedArtifactVersion=n` | 204 | FINALIZED → 409 `ARTIFACT_ALREADY_FINALIZED`; stale → 409 `ARTIFACT_VERSION_CONFLICT`; missing → 404 `ARTIFACT_NOT_FOUND`; non-certificate draft → **409 `ARTIFACT_NOT_DISCARDABLE` (new)** |
| `DELETE /doctor/consultations/{id}/prescription?expectedPrescriptionVersion=n` | 200 `PrescriptionResponse` (`status NONE`, `prescriptionVersion n+1` = what the next PUT sends) | signed → 409 `PRESCRIPTION_ALREADY_FINALIZED`; stale → 409 `PRESCRIPTION_VERSION_CONFLICT`; no draft → 404 `PRESCRIPTION_NOT_FOUND` |

- All three: role DOCTOR, the same `ActiveClinicalContextGuard` as the writes (another doctor's consultation → 404 `RESOURCE_NOT_FOUND`, MRS not called; after Finish → 409 `CONSULTATION_ALREADY_COMPLETED` / `CONSULTATION_FINALIZING` / `CONSULTATION_FINALIZED`), `Idempotency-Key` required and replayed, realtime `*_UPDATED` published, `Cache-Control: no-store`. A bad version parameter is a 400 `VALIDATION_ERROR` with a French field error.
- MRS: new internal routes `POST …/discard`, the same finalization fence and patient-row lock as the other writes, audit operations `CLINICAL_ORDER_DRAFT_DISCARDED`, `ARTIFACT_DRAFT_DISCARDED`, `PRESCRIPTION_DRAFT_DISCARDED` (ids only).
- Storage: the prescription draft is marked `DELETED` (existing status; the append-only series and integrity checks are untouched; every read/sign/readiness query ignores it). **Draft orders and draft certificates are hard-deleted** (mutable rows, nothing references a draft; only the audit event remains).
- `ClinicalValidationAdvice` now also turns a missing/mistyped query parameter and `ConstraintViolationException` into the 400 contract on the 4 doctor controllers (they used to fall into the 500 catch-all).
- Angular uses all three (§3.2) and treats a 404 on discard as already discarded.

## 7. Points reported (interpretations, not decisions)

1. **Antécédents label « Aucun connu »** (allergies keep « Aucune connue »). The prompt says « Aucune connue » for both, but antécédents is masculine and the 2a server catalog already says « Choisissez « Aucun connu » ou ajoutez au moins un antécédent ». **Confirm** or I align the server text the other way.
2. **A resource that fails its own Hard rules is not sent.** The note always saves without the finish fields (only lengths and dates block it). But a medication line, an order or a certificate cannot exist on the server half-filled (v3 / 2a require every field), so it stays in memory with « Non enregistré · champs à corriger », and `beforeunload` and the router guard protect it. This label is a fifth indicator state, added to the four in the prompt.
3. **Diagnostic status defaults to « Provisoire »** (the server requires a status as soon as a label exists).
4. **« Aucun examen » / document toggles are not stored server-side.** On reload they are derived from whether orders or certificates exist. The arrêt de travail start date defaults to today.
5. **No long-term (« au long cours ») option** on this page, because the prompt's line fields don't list it: duration is required. v2/v3 drafts carrying `longTerm` are kept as is.
6. **Changing the type of an already-saved order** sends the new category in the PUT. Not exercised against the real backend yet; if MRS refuses a category change, the error shows on the row (then we should lock the type after the first save).
7. **Realtime multi-tab refresh is not wired into the new page** (the old stores listened to `CONSULTATION_UPDATED`). A second tab's edits surface as a 409 → banner → « Recharger ». Say if you want the passive « une version plus récente est disponible » back.
8. **FINALIZING after a reload** polls for 2 minutes and offers « Réessayer » (re-poll). « Reprendre la finalisation » / abort stays for prompt 3, as does « Annuler la consultation » (not shown).
9. **Test-bundler quirk.** When two consultation specs ran together, module constants captured in component *fields* were `undefined` at construction (the Angular unit-test builder shares chunks between spec entry points; no source import cycle exists). Those fields are now getters. Production lazy chunks are unaffected, but this is why the getters exist.
10. **Vitals (« Constantes ») stay hidden**: no backend storage (unchanged decision).
